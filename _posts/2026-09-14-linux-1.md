# 리눅스 공부 기록 1일차: 리눅스 실습을 위한 가상 환경 구축 및 기본 설정

이번 포스팅은 총 3시간 동안 진행된 리눅스 첫 수업의 내용을 복습하고 기록하기 위해 작성했습니다. 본격적인 리눅스 명령어 학습이나 서버 구축 실습에 앞서, 윈도우(Host OS) 환경 위에 4대의 가상 머신(Client1, Client2, Server1, Server2)을 세팅하는 과정을 정리했습니다.

## 수업 전체 개요 및 목표

이번 수업의 핵심은 앞으로 진행될 클라이언트-서버 간의 네트워크 통신 및 패키지 설치 실습을 위한 뼈대를 만드는 것이었습니다.

구축한 환경: CentOS Stream 9 기반의 가상 머신 4대 (Client1, Client2, Server1, Server2)
설치한 프로그램: VMware Workstation Pro 16, CentOS Stream 9
주요 변경 설정: 정적 IP 할당, 호스트네임(Hostname) 식별자 부여, 최고 관리자(root) 원격 접속(SSH) 허용
진행 흐름: 실습 파일 확보 -> 기본 가상 머신(Client1) 생성 및 OS 설치 -> 네트워크 검증 -> 가상 머신 복제(클론) -> 나머지 3대의 개별 호스트명 및 IP 부여 -> 최종 통신 확인

## 환경 구축 과정 상세 기록

### [단계 1] 실습 파일 다운로드 및 준비 (Host OS)
학원 PC 환경과 개인 노트북 환경에 따라 파일 확보 방식이 달랐습니다.
학원 PC: Win + R 실행창에서 \192.168.11.30 입력 후, Users > 김정우_공유폴더 > 리눅스 폴더를 복사하여 D:\Korea-Data (D:) 내에 개인 폴더를 만들어 붙여넣었습니다.
개인/비대면: 브라우저에서 http://183.98.32.210 접속 후 ID(linux1), PW(linux5678!$)를 입력하여 파일을 다운로드하고 압축을 해제했습니다.

### [단계 2] 기본 가상 머신(Client1) 생성
VMware Workstation Pro 16을 실행하고 File > New Virtual Machine을 클릭했습니다. 설정은 Typical (recommended)을 선택하고, OS 설치는 I will install the operating system later를 선택하여 껍데기 가상 머신을 먼저 만들었습니다.

### [단계 3] CentOS Stream 9 설치 및 초기 설정 (Guest OS)
네트워크/호스트명: 설치 화면에서 호스트 이름을 Client1로 지정했습니다.
root 암호 설정: 비밀번호를 centos로 입력하고, 'root가 비밀번호로 SSH 로그인하도록 허용'에 체크했습니다.
일반 사용자 생성: 이름과 비밀번호를 fedora로 지정하고 '이 사용자를 관리자로 설정합니다'에 체크했습니다.
설치 진행: '설치 시작'을 누르고 완료 후 시스템을 재시작했습니다.

### [단계 4] 로그인 및 Client1 네트워크 검증
재부팅 후 GUI 화면에서 기본으로 뜨는 fedora를 누르지 않고, '목록에 없습니까?'를 클릭하여 사용자 root, 비밀번호 centos로 로그인했습니다. 이후 바탕화면에서 터미널을 열고 네트워크 상태를 점검했습니다.

### [단계 5] 추가 가상 머신 설정 (Client2, Server1, Server2)
VMware 기능을 통해 Client1을 3개 더 복제한 뒤 각각 설정을 변경했습니다.
호스트명 변경: 각 터미널에서 hostnamectl set-hostname [변경할이름] 실행 후 터미널을 재시작했습니다.
네트워크 IP 변경: 터미널에 nm-connection-editor & 입력하여 GUI 창을 띄우고, ens33의 IPv4 설정 탭에서 IP 주소를 202, 203, 204로 각각 변경했습니다.
설정 적용: nmcli connection up ens33 && systemctl restart NetworkManager 명령어를 실행하여 변경된 IP를 시스템에 즉시 반영했습니다.

## 실습에 사용된 터미널 명령어 정리

ip address: ens33 인터페이스에 할당된 IP(예: 192.168.2.201/24)를 확인했습니다.
clear: 터미널 화면을 지웠습니다. (단축키 Ctrl + L과 동일)
ip route: 기본 게이트웨이(default via 192.168.2.254 dev ens33)가 정상적으로 설정되었는지 확인했습니다.
cat /etc/resolv.conf: DNS 설정 파일을 출력하여 nameserver 168.126.63.1이 등록되어 있는지 확인했습니다.
ping -c 3 168.126.63.1: 외부 목적지로 패킷을 3번 보내 통신 성공 여부를 테스트했습니다.
hostnamectl set-hostname [이름]: 호스트네임을 변경했습니다. 적용 후에는 터미널을 닫고 다시 열어야 프롬프트에 반영되었습니다.
nm-connection-editor &: 네트워크 설정 GUI 툴을 백그라운드 프로세스로 실행했습니다.
nmcli connection up ens33: ens33 네트워크 인터페이스를 활성화했습니다.
systemctl restart NetworkManager: 네트워크 데몬을 재시작하여 변경된 IP 정보를 시스템에 즉시 적용했습니다.

## 주요 파일 및 디렉터리 경로

\192.168.11.30: (Windows) 실습용 파일이 들어있는 학원 내부 네트워크 공유 폴더입니다.
/etc/resolv.conf: (Linux) 시스템이 사용할 외부 DNS 서버 주소가 저장된 파일입니다.
~ : 터미널 프롬프트 [root@Client1 ~]#에서 물결표시는 현재 위치가 해당 사용자(root)의 홈 디렉터리임을 의미합니다.

## 설정 및 환경변수 요약

### 네트워크 설정 (인터페이스: ens33)
Client1 (기본): 192.168.2.201
Client2: 192.168.2.202
Server1: 192.168.2.203
Server2: 192.168.2.204
Subnet: /24 (255.255.255.0)
Gateway: 192.168.2.254
DNS: 168.126.63.1

### 사용자 및 권한 설정
root: 최고 관리자. 비밀번호는 centos, SSH 원격 접근을 허용했습니다.
fedora: 일반 사용자. 비밀번호는 fedora, 관리자 권한을 부여했습니다.

## 설치 중 발생한 오류 및 해결 과정 (Troubleshooting)

Windows 11 코어 격리 충돌: 수업 초반 VMware 실행 전, 윈도우 11의 메모리 무결성 보안 정책이 가상화 동작을 차단하는 문제가 있었습니다. 윈도우 검색창에서 '코어 격리'를 검색해 해당 기능을 '끔'으로 변경하여 해결했습니다.
마우스 갇힘 현상: 가상 머신 내부를 클릭한 뒤 윈도우로 마우스가 나오지 않을 때는 키보드 Ctrl + Alt를 눌러 제어권을 가져왔습니다.
프롬프트 호스트명 미적용: hostnamectl 명령어로 이름을 변경해도 현재 실행 중인 쉘에는 즉시 반영되지 않았습니다. 열려있던 터미널 창을 닫고 새 터미널을 실행하여 해결했습니다.
터미널 붙여넣기 실패: 메모장의 명령어를 터미널에 붙여넣을 때 윈도우 단축키인 Ctrl + V가 먹히지 않았습니다. 리눅스 터미널용 단축키인 Shift + Insert를 사용하거나 마우스 우클릭을 활용해야 했습니다.

## 새롭게 학습한 리눅스 개념

Virtual Machine (가상 머신)과 Host/Guest OS: 윈도우(Host)의 물리적 자원을 쪼개어 가상의 하드웨어를 만들고, 그 위에 리눅스(Guest)를 설치하는 개념을 배웠습니다.
리눅스 배포판: 수많은 리눅스 중 레드햇 계열의 CentOS Stream 9을 실습용으로 사용했습니다.
root 계정: 시스템의 모든 권한을 가진 최고 관리자이며 프롬프트 끝이 #으로 끝나는 것을 확인했습니다.
백그라운드 프로세스 (&): nm-connection-editor & 명령어처럼 끝에 &를 붙이면 터미널 제어권을 잃지 않고 GUI 프로그램을 백그라운드에서 실행할 수 있습니다.
데몬/서비스: 백그라운드에서 동작하는 시스템 관리 프로그램으로, systemctl 명령어를 이용해 NetworkManager 서비스를 제어했습니다.

## 정보보안 관점에서의 설정 의미

root SSH 로그인 허용: 실무에서는 최고 관리자의 외부 원격 직접 접속을 엄격히 차단하지만, 수업 편의상 의도적으로 허용했습니다.
취약한 비밀번호: 관리자 암호를 centos, 일반 계정을 fedora로 설정한 것은 실무의 비밀번호 복잡도 정책에 크게 위배되는 교육용 세팅입니다.
GUI root 로그인 경고: root 계정으로 GUI 환경에 접속하면 운영체제 자체에서 "보안 이유로 피해야 합니다"라는 경고 알림을 띄웁니다.
코어 격리 해제: 가상화 실습을 위해 Host OS(윈도우)의 보안 샌드박스 기능을 일부 해제하는 트레이드오프가 있었습니다.

## 주의 사항

Client1 절대 조작 금지: 네트워크 변경 실습 시, 기본이 되는 Client1은 설정이 완료된 기준점이므로 절대 호스트명이나 IP를 변경하지 말라고 거듭 강조하셨습니다.
로그인 방식 주의: 부팅 후 무심코 fedora 계정을 누르지 말고, 반드시 '목록에 없습니까?'를 통해 root 계정으로 접속해야 이후 권한 문제 없이 실습이 가능합니다.
직접 검증하는 습관: OS 설치가 끝났다고 넘어가면 안 되며, 터미널을 열어 ip address와 ping 명령어 등을 통해 통신 정상 여부를 반드시 눈으로 확인해야 합니다.
공유 폴더 훼손 금지: 파일 복사 시 '잘라내기'를 하면 다른 사람이 실습할 수 없으므로 무조건 '복사'를 사용해야 합니다.

## 최종 구축된 실습 환경 상태

OS / Linux 배포판: CentOS Stream 9
Shell: bash 쉘 (프롬프트 형태: [root@호스트명 ~]#)
사용자: root (비밀번호: centos), fedora (비밀번호: fedora)
네트워크 설정: 인터페이스 ens33, IP 대역 192.168.2.201~204, 게이트웨이 192.168.2.254, DNS 168.126.63.1
기타 설정: root 계정 SSH 원격 접속 활성화 완료
이후 수업: 이 4대의 노드를 통해 네트워크 명령어 및 서버-클라이언트 아키텍처 실습을 진행하게 됩니다.
