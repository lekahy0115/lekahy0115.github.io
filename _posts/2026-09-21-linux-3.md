# Linux 시스템 기본 명령어 II 및 쉘(Shell) 메타캐릭터 통합 학습 기록

---

## 1. 수업 전체 개요

본 학습 기록은 Linux 시스템의 파일 유형 식별부터 패턴 검색, 환경 변수와 경로 탐색 메커니즘, 계정 전환, 그리고 쉘(Shell)의 아키텍처와 메타캐릭터(특수 문자 및 제어 연산자) 처리 원리까지 이어지는 전체 수업 과정을 하나로 통합하여 정리한 기술 문서이다.

### 수업 전체의 주요 학습 내용 및 주제
* **이전 과정 핵심 복습**: 파일 및 디렉터리 제어 기본 명령어(`pwd`, `cd`, `ls`, `mkdir`, `rmdir`, `rm`, `cp`, `mv`, `touch`, `cat`, `more`, `less`, `head`, `tail`)와 기본 기호(`{}`, `[]`, `*`, `;`, `|`, `/`)의 역할 재점검.
* **파일 유형 식별과 컴퓨터 아키텍처 기초**: `file` 명령어를 통한 텍스트(ASCII text), 디렉터리(Directory), 실행 바이너리(ELF), 시스템 데이터(Data), 쉘 스크립트(Shell Script) 구분. 7비트 ASCII 코드와 유니코드의 관계, 소스 코드의 컴파일 및 기계어/어셈블리어 변환 원리.
* **패턴 검색과 정규 표현식 기초**: `grep`과 `egrep`을 활용한 문자열 검색, 단어 단위 검색(`-w`), 라인의 시작(`^`)과 끝(`$`)을 지정하는 앵커 메타문자, 완전 일치(`^...$`) 검증.
* **시스템 환경 변수와 파일 탐색 체계**: `env`와 `echo`를 이용한 환경 변수 조회, 명령어 자동 탐색 경로인 `PATH` 환경 변수의 동작 원리(Linux vs Windows 비교), 명령어 및 파일 위치 검색 도구(`whereis`, `which`, `find`)의 탐색 범위 비교.
* **통계 산출 및 사용자 계정 전환**: `wc` 명령어와 파이프라인(`|`)을 결합한 패키지/프로세스/파일 개수 카운팅, `su` 및 `su -`를 통한 계정 전환과 권한 검증.
* **쉘(Shell) 아키텍처와 메타캐릭터 제어**: 사용자와 커널을 중계하는 `bash` 쉘의 프로세스 계층 구조(`PID`/`PPID`), 명령어 순차/조건부 실행 연산자(`;`, `&&`, `||`), 명령어 치환(`` ` ``, `$()`), 메타캐릭터 무력화 기법(`\`, `' '`, `" "`), 문자 집합(`[]`) 및 자릿수 매칭(`.`).

### 전체 수업에서 다룬 내용의 연결 관계
수업은 "Linux에서 모든 것은 파일이다"라는 명제를 `file` 명령어로 증명하며 시작된다. 우리가 터미널에 입력하는 명령어(`ls`, `mkdir`)가 실제로는 `/usr/bin` 등에 위치한 ELF 바이너리 실행 파일임을 확인한 뒤, 어떻게 경로 입력 없이 명령어 이름만으로 실행할 수 있는지에 대한 해답으로 `PATH` 환경 변수와 쉘(Shell)의 탐색 메커니즘을 연결한다. 또한 전반부의 `grep` 실습에서 등장한 정규 표현식 기호(`^`, `$`, `*`, `.`, `[]`)와 파이프(`|`)를 후반부의 쉘 메타캐릭터 및 이스케이프/쿼팅 규칙(`\`, `' '`, `" "`)으로 통합하여, 쉘이 명령어를 파싱하고 프로세스를 제어하는 전체 흐름을 완성한다.

## 2. Linux 개념 및 이론 통합 정리

### 2.1 전 시간 기본 명령어 및 특수 기호 복습
강사는 본 수업에 앞서 지난 시간에 학습한 파일 및 디렉터리 관리 명령어와 주요 옵션을 메모장에 나열하며 핵심 기능을 정리하였다.

* **`pwd`**: 현재 작업 디렉터리(Print Working Directory)의 경로를 확인한다.
* **`cd`**: 작업 디렉터리를 이동(Change Directory)한다.
* **`ls`**: 디렉터리 내부 목록이나 파일 정보를 확인한다.
  * 필수 암기 옵션: `-l`(상세 정보 출력), `-a`(숨김 파일 포함 전체 출력), `-i`(inode 번호 출력).
  * 추가 주요 옵션: `-ld`(디렉터리 자체의 상세 정보 출력, `-d`만 단독으로 쓰면 의미가 없음), `-R`(하위 디렉터리 목록까지 재귀적으로 출력).
* **`mkdir`**: 디렉터리를 생성한다. 주요 옵션으로 `-p`(상위 경로까지 일괄 생성)와 `-m`(권한 지정, 추후 학습 예정)이 있다.
* **`rmdir`**: 비어 있는 디렉터리를 삭제한다.
* **`rm`**: 파일이나 디렉터리를 삭제한다. 디렉터리 삭제 시에는 `-r`(재귀) 옵션을 반드시 넣어야 하며, 강제 삭제 옵션인 `-f`와 결합하여 통상 `-rf` 형태로 함께 사용한다.
* **`cp`**: 파일이나 디렉터리를 복사한다. 주요 옵션으로 `-p`(원본 파일의 소유권, 권한, 시간 등 속성 유지), `-r`(디렉터리 복사), `-i`(덮어쓰기 여부 대화형 확인)가 있다.
* **`mv`**: 파일 및 디렉터리의 이름을 변경하거나 다른 디렉터리로 이동시킨다. 덮어쓰기 여부를 묻는 `-i` 옵션 정도만 알아두면 된다.
* **`touch`**: 빈 파일을 생성하거나 기존 파일/디렉터리의 날짜 및 시간 정보(타임스탬프)를 변경한다. 수동으로 시간을 지정할 때는 `-t` 옵션을 사용한다.
* **`cat`**: 원래 파일과 파일을 나열하거나 상태를 연결(Concatenate)하는 역할을 하지만, 실무에서는 텍스트(글자)로 이루어진 파일의 내용을 확인할 때 가장 빈번하게 사용한다. `-n` 옵션을 주면 좌측에 라인 번호가 함께 출력된다.
* **`more` / `less`**: 출력되는 내용이 많을 때 화면 단위로 끊어서 출력한다. `more` 실행 중 `Spacebar`는 한 페이지 이동, `Enter`는 한 줄 이동, `q`는 종료이다. `less`도 유사한 기능을 수행한다.
* **`head` / `tail`**: 파일의 앞부분(`head`) 또는 끝부분(`tail`)을 기준으로 지정한 라인 수(`-n`, 생략 가능) 또는 글자/바이트 수(`-c`)만큼 출력한다.
* **슬래시(`/`) 기호의 다중 의미**:
  * 경로의 맨 앞에 단독으로 쓰이거나 시작될 때는 최상위 **루트 디렉터리(Root Directory)**를 의미한다.
  * 경로 중간(예: `/etc/passwd`)에 쓰일 때는 디렉터리와 파일을 구분하는 **경로 구분자** 역할을 한다.
  * 디렉터리 이름 뒤에 붙어 **'이 항목은 디렉터리입니다'**라고 표기하는 용도로도 사용된다.

### 2.2 파일 유형 분류와 실행 파일 아키텍처

#### 1) Linux의 파일 유형 분류
Linux에서는 일반 텍스트뿐만 아니라 디렉터리와 시스템 명령어까지 모두 파일의 일종으로 취급한다. 확장자에 의존하는 Windows와 달리, Linux는 확장자에 관계없이 파일 내부의 데이터 구조로 유형을 판별하며, 이를 확인하는 도구가 `file` 명령어이다.

| 파일 유형 | `file` 명령어 출력 형태 | 내부 구조 및 특징 | 텍스트 뷰어(`cat`) 열람 여부 |
| :--- | :--- | :--- | :--- |
| **일반 텍스트** | `ASCII text` | 7비트 ASCII 문자 인코딩으로 작성된 순수 글자 파일 | 열람 가능 (`cat`, `more`, `head`, `tail` 등) |
| **디렉터리** | `directory` | 하위 파일 및 폴더의 목록 정보를 담고 있는 특수 파일 | 열람 불가 (`ls`로 목록 확인) |
| **바이너리 실행 파일** | `ELF 64-bit LSB pie executable...` | 컴파일러를 통해 기계어(바이너리)로 변환된 프로그램 | 열람 불가 (출력 시 터미널 문자 깨짐 발생) |
| **시스템 데이터** | `data` | 글자와 이진 데이터, 또는 암호화된 정보 등이 혼합된 특수 파일 | 정상 열람 불가 (데이터 영역이 깨져서 출력됨) |
| **쉘 스크립트** | `... sh script, ASCII text executable` | 글자(코드)로 작성되어 인터프리터가 해석하는 실행 파일 (주로 `.sh`로 끝남) | 열람 가능 (`cat`으로 내부 소스 코드 확인 가능) |

#### 2) 문자 인코딩: ASCII 코드와 유니코드(Unicode)
* **ASCII (American Standard Code for Information Interchange)**:
  * 미국에서 정의한 표준 영문 문자 인코딩 규격으로, 문자를 **7비트(7-bit)** 이진수로 표현한다.
  * 강사가 위키백과 ASCII 코드표를 통해 설명한 예시:
    * 대문자 `'A'`: 2진수 `1000001`(7비트), 10진수 `65`, 16진수 `41`.
    * 소문자 `'a'`: 2진수 `1100001`(7비트), 10진수 `97`, 16진수 `61`.
  * 사용자가 키보드로 `'a'`를 입력하면 컴퓨터는 내부적으로 이진수 `1100001`로 받아들여 처리한다.
* **유니코드 (Unicode)**:
  * 전 세계의 모든 문자를 표현하기 위한 통합 코드 체계이다.
  * 유니코드라는 거대한 집합 안에 ASCII 코드가 부분집합으로 포함되어 있는 구조이다.

#### 3) 소스 코드 컴파일과 ELF 실행 파일 구조
* **ELF (Executable and Linkable Format)**:
  * Linux의 표준 바이너리 실행 파일 포맷이다. 앞글자 E가 `Executable`(실행 파일)을 의미한다.
  * Windows 환경에서 실행 파일 확장자로 흔히 보는 `.exe` 역시 `executable`의 앞 세 글자를 딴 것이며, Windows의 실행 파일 포맷은 **PE(Portable Executable)** 파일이라고 부른다.
* **컴파일(Compile)과 어셈블리(Assembly)**:
  ```text
  [소스 코드 작성] ──(컴파일러)──> [실행 파일(프로그램): 기계어(0과 1)] ──(역어셈블)──> [어셈블리어]
  ```
  1. 개발자가 작성한 소스 코드를 **컴파일러(Compiler)**를 통해 컴파일링하면 실행 파일(프로그램)이 제작된다.
  2. 이 실행 파일 내부에는 PC의 CPU가 알아들을 수 있는 언어인 **기계어(바이너리, 0과 1의 조합)**가 들어 있다. (도움말 출력 등을 위한 일부 문자열이 포함될 수는 있으나 본질은 기계어이다.)
  3. 기계어는 0과 1의 숫자로만 되어 있어 사람이 직접 읽을 수 없다. 사람이 이를 읽고 분석하려면 기계어를 원초적인 저수준 언어인 **어셈블리어(Assembly)**로 변환하여 읽어야만 한다.

### 2.3 환경 변수(Environment Variables)와 명령어 탐색 경로

#### 1) 환경 변수의 정의와 특징
* **개념**: C언어, 파이썬, 자바 등 프로그래밍 언어에서 변하는 값을 저장하는 '변수(Variable)' 개념과 동일하며, Linux 운영체제 및 쉘이 동작하는 시스템 환경 설정 값을 저장하는 변수이다.
* **`env` (environment)**: IT 용어로 시스템의 작업 공간(환경)을 뜻하는 `environment`의 앞 세 글자를 딴 명령어로, 현재 시스템에 설정된 환경 변수 목록을 `변수이름=변수값` 형태로 출력한다.
* **명명 관례**: 변수 이름을 대문자나 소문자로 정하는 강제 규칙은 없으나, 환경 변수로 사용할 때는 관례상 **대문자**로 작성한다.
* **주요 기본 환경 변수**:
  * `SHELL=/bin/bash`: 현재 사용 중인 쉘 프로그램 경로.
  * `HOSTNAME=Client1`: 현재 시스템의 호스트 이름.
  * `PWD=/root`: 현재 작업 디렉터리 경로 (`cd /etc` 등으로 이동하면 `PWD=/etc`로 자동 변경됨).
  * `LOGNAME=root` / `USER=root`: 현재 로그인한 사용자 계정 이름.

#### 2) `PATH` 환경 변수의 필요성과 동작 원리
* **`PATH` 환경 변수의 역할**:
  * 콜론(`:`)을 구분자로 하여 여러 개의 디렉터리 경로(예: `/root/.local/bin:/root/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin`)를 등록해 둔 변수이다.
  * 여기에 등록된 디렉터리 내부에 존재하는 실행 파일들은 사용자가 현재 **어떤 작업 디렉터리에 있든 관계없이 경로 지정을 생략하고 명령어 이름만으로 검색하여 즉시 실행**해 준다.
* **과거 컴퓨터 환경과의 비교**:
  * 과거 8비트, 16비트 컴퓨터 시절에는 `PATH` 개념이 없거나 미비하여 프로그램을 실행하려면 해당 실행 파일이 있는 디렉터리까지 직접 이동(`cd /usr/bin` 후 `ls`)하거나, 전체 경로(`/usr/bin/ls`)를 일일이 입력해야 하는 큰 불편함이 있었다.
  * `PATH` 환경 변수는 사용자가 `ls`나 `ifconfig`만 입력해도 쉘이 `PATH`에 등록된 디렉터리들을 순차 검색하여 해당 프로그램을 찾아 실행해 주므로 작업 편의성을 극대화한다. (`time ifconfig`로 측정 시 탐색 및 실행에 총 `0.002초`밖에 걸리지 않을 정도로 빠르게 처리된다.)
* **Windows의 `Path` 환경 변수와의 비교**:
  * Windows에서도 명령 프롬프트(`cmd`)의 `C:\Users\Administrator>` 경로에 `ipconfig.exe` 파일이 없지만 `ipconfig` 명령이 실행된다.
  * 이는 Windows의 기본 명령어 실행 파일들이 모여 있는 `C:\Windows\System32` 디렉터리가 Windows의 **시스템 환경 변수 `Path`**에 등록되어 있기 때문이다.
  * Windows 환경 변수는 특정 계정만 사용하는 **사용자 변수**와 모든 계정이 공통으로 사용하는 **시스템 변수**로 나뉜다. 과거에는 파이썬(Python) 등을 설치하면 사용자가 직접 설치 경로를 `Path`에 수동 등록해야 했으나, 최근 프로그램들은 설치 시 자동으로 등록해 준다.

### 2.4 파일 및 명령어 검색 도구의 비교: `whereis`, `which`, `find`

Linux에서 파일이나 명령어의 위치를 찾는 세 가지 도구는 탐색 범위와 목적에 명확한 차이가 있다.

| 명령어 | 검색 대상 및 범위 | 주요 특징 및 출력 정보 |
| :--- | :--- | :--- |
| **`whereis`** | `$PATH`에 국한되지 않고 시스템 표준 경로 전체에서 파일 검색 | 실행 파일뿐만 아니라 설정 파일(`/etc/passwd` 등), 매뉴얼 페이지(`man`) 파일까지 폭넓게 찾아준다 (`which`보다 검색 범위가 큼). |
| **`which`** | 오직 **`$PATH` 환경 변수에 등록된 디렉터리 내부**에서만 검색 | 해당 명령어가 `alias`(별칭)로 설정되어 있는 경우 `alias` 설정 정보까지 함께 보여준다. |
| **`find`** | 사용자가 지정한 시작 디렉터리부터 하위 트리 전체를 실시간 정밀 검색 | Windows 탐색기의 검색 창과 동일한 역할. 이름(`-name`), 파일 유형(`-type f`, `-type d`) 등 다양한 조건 조합이 가능한 가장 강력한 검색 도구이다. |

* **`find` 옵션 표기 주의사항**: 일반적으로 Linux 명령어에서 한 글자 옵션은 대시 하나(`-`), 단어 형태의 긴 옵션은 대시 두 개(`--`)를 쓰지만(예: `--help`), **`find` 명령어는 예외적으로 단어 형태의 옵션에도 대시 하나(`-name`, `-type`)만 사용한다**.
* **Linux의 환경 구성 파일 관례**: `/etc` 디렉터리에는 시스템 환경 구성(설정) 파일들이 모여 있다. Linux는 파일 확장자에 큰 의미를 두지 않고 명령어의 인자값으로 파일 경로만 정확히 들어가면 동작하지만, 관리자가 식별하기 쉽도록 환경 구성 파일들은 주로 **`.conf`, `.cfg`, `.cf`**로 끝나는 이름을 사용한다.

### 2.5 시스템 통계(`wc`) 및 계정 전환(`su`)

#### 1) `wc` (Word Count)
* 표준 출력 또는 지정한 파일에 포함된 **라인(줄) 수(`-l`), 단어 수(`-w`), 문자(바이트) 수(`-c`)**를 집계하여 출력하는 명령어이다.
* 단독으로 쓰기보다는 다른 명령어의 출력 결과를 파이프(`|`)로 넘겨받아 `wc -l`(라인 수 계산)을 수행함으로써, **설치된 패키지 총 개수(`rpm -qa | wc -l`)**나 **실행 중인 프로세스 개수(`ps -ef | wc -l`)**, **디렉터리 내 파일 개수(`ls -l /etc | wc -l`)**를 파악할 때 실무에서 매우 유용하게 사용된다.

#### 2) 계정 전환: `su` vs `su -`
* 현재 로그인한 쉘 환경에서 로그아웃하지 않고 다른 사용자 계정으로 전환(로그인)할 때 사용한다.
* **인증 규칙**: 최고 관리자인 `root` 계정에서 일반 사용자(`user1`)로 전환할 때는 암호를 묻지 않지만, 일반 사용자에서 다른 일반 사용자(`user1` $\rightarrow$ `user2`)나 `root`로 전환할 때는 반드시 대상 계정의 암호를 입력해야 한다. 전환된 상태에서 `exit`를 입력하면 이전 계정으로 단계별로 로그아웃되어 돌아간다.
* **하이픈(`-`) 옵션 유무의 핵심 차이**:
  * **`su 계정명` (예: `su user1`)**: 이전 계정(`root`)의 환경 변수를 그대로 유지한 채 계정만 전환한다.
  * **`su - 계정명` (예: `su - user1`)**: 로그인 쉘을 새로 구동하여 전환 대상 계정(`user1`) 고유의 환경 변수와 작업 디렉터리를 완전히 불러와 사용한다.

### 2.6 쉘(Shell)의 아키텍처와 메타캐릭터(Metacharacters) 통합

#### 1) 쉘(Shell)의 역할과 프로세스 구조
* **정의**: 표준 입력으로 입력한 명령어나 스크립트 파일에서 읽어들인 명령어를 해석하여 **사용자(사람)와 커널(Kernel) 사이를 중계**하는 프로그램이다.
  ```text
  [사용자 입력: ls -l /tmp] ───> [ 쉘 (Shell): 명령어 해석 ] ───> [ 커널 (Kernel): 01010101 처리 및 응답 ]
  ```
* **쉘의 종류**: `sh`, `csh`, `ksh`, `tcsh`, `ash`, `bash`, `zsh` 등이 있으며, 현재 Linux에서 가장 표준적으로 널리 사용되는 기본 쉘은 **`bash` (`/bin/bash`)**이다. (`root`와 일반 계정 모두 로그인 시 기본적으로 `bash`가 실행된다.)
* **부모 프로세스로서의 쉘**: 터미널에서 명령어를 입력하면 모두 `bash` 쉘이 받아서 처리한다. `ps -ef`로 프로세스 목록을 확인해보면, 방금 실행한 `ps -ef` 프로세스의 부모 프로세스 ID(`PPID`)가 바로 현재 터미널의 `-bash` 프로세스 ID(`PID`)로 나타나며, 이를 통해 `bash`가 모든 실행 명령어의 부모 역할을 함을 확인할 수 있다.

#### 2) 메타캐릭터(Metacharacter)와 정규 표현식(Regular Expression)
* **개념**: 쉘이나 텍스트 처리 도구가 단순한 글자로 받아들이지 않고 **특별한 의미(기능)로 해석하는 특수 문자 또는 기호**를 Linux에서는 **메타캐릭터(Metacharacter)**라고 부른다.
* 프로그래밍 분야에서는 이러한 문자열 패턴 표기 규칙을 **Regular Expression(줄여서 Regex, 레직스)**, 우리말(한자어)로는 **정규 표현식(정규형 문자 표기법)**이라고 부른다. Linux뿐만 아니라 다른 프로그래밍 언어에서도 공통적으로 동일하게 사용된다.

#### 3) 수업 전체에서 다룬 메타캐릭터 총정리

##### ① 파이프 및 명령어 연속/조건부 실행 연산자
| 기호 | 명칭 | 동작 원리 및 실행 조건 | 특징 및 활용 |
| :--- | :--- | :--- | :--- |
| **`\|`** | 파이프 (Pipe) | 앞에 실행한 명령어의 표준 출력 결과를 뒤에 오는 명령어의 입력으로 넘겨준다. | 따옴표나 소괄호 안(예: `egrep "^root\|user"`)에서 사용되면 **OR(또는)** 조건으로 동작한다. |
| **`;`** | 세미콜론 | 여러 개의 명령어를 순차적으로 실행한다. **앞의 명령어가 실패(오류)하더라도 뒤의 명령어를 무조건 실행**한다. | 횟수 제한 없이 여러 번 연결 가능. 앞 명령의 성패와 무관하게 무조건 자기 차례가 오므로 공격자의 **OS Command Injection** 공격에 주로 악용된다. |
| **`&&`** | 더블 앰퍼샌드 | 여러 개의 명령어를 순차 실행하되, **앞의 명령어가 성공했을 때만 뒤의 명령어를 실행**한다 (앞이 실패하면 뒤는 실행 안 함). | 선행 작업(B)이 성공해야만 후행 작업(A)이 의미가 있는 **의존성(Dependency)** 관계의 명령들을 묶을 때 적합하다. |
| **`\|\|`** | 더블 버티컬 바 | **앞의 명령어가 성공하면 뒤의 명령어를 실행하지 않고, 앞의 명령어가 실패했을 때만 뒤의 명령어를 실행**한다. | 앞선 명령어의 오류 발생 시 대체 명령어를 실행할 때 사용한다. |

##### ② 위치 지정(앵커) 및 변수 참조 기호: `^`, `$`
* **`^` (캐럿 / 꺾쇠)**:
  * 정규 표현식에서 **라인의 시작**을 의미한다. (예: `^telnet`은 라인 맨 앞이 `telnet`으로 시작하는 줄만 검색.)
  * 강사의 암기 팁: 육상 100m 달리기 선수가 출발선(라인)에 엎드려 있는 스타트 자세(`^`)를 연상하면 '라인의 시작'으로 외우기 쉽다.
* **`$` (달러)의 위치별 이중 의미**:
  * **문자열 뒤에 올 때 (`문자$` 형태, 예: `Controller$`, `bash$`)**: 정규 표현식에서 **라인의 끝**을 의미한다. (강사의 암기 팁: "돈(`$`) 없으면 끝이다"로 연상.)
  * **문자열 앞에 올 때 (`$문자` 형태, 예: `$PATH`, `$SHELL`)**: 쉘에서 뒤따라오는 문자를 일반 텍스트가 아닌 **변수 이름**으로 처리하여 그 안에 들어있는 변수값을 불러온다. (웹 개발 언어들에서도 변수 선언 시 앞에 `$`를 붙이는 경우가 많다.)
* **`^패턴$` 결합 (예: `^test$`)**: 라인의 시작이 `test`이고 라인의 끝도 `test`라는 뜻으로, 한 줄에 다른 어떠한 글자나 공백도 없이 **오직 `test`라는 단어 딱 하나만 단독으로 존재하는 라인**만 성립한다.

##### ③ 와일드카드 및 자릿수/범위 지정 기호: `*`, `.`, `{ }`, `[ ]`
* **`*` (애스터리스크 / 별)**: 길이와 글자 수에 제한 없이 **전체(모든 문자, 0글자 이상 무제한)**를 의미한다.
  * `pass*`: `pass`로 시작하는 모든 것.
  * `*conf`: `conf`로 끝나는 모든 것.
  * `file*`: `file` 자체(뒤에 0글자)를 포함하여 `file`로 시작하는 모든 이름.
* **`.` (피리어드 / 점)**: 정확히 **한 자리의 모든 문자 또는 숫자**를 의미한다.
  * `file.`은 `file` 뒤에 아무 글자나 딱 1글자가 붙은 **무조건 5글자짜리 이름**만 해당된다(`file`만 있는 4글자는 해당 안 됨).
  * `file..`은 5번째, 6번째 자리에 모든 문자가 올 수 있는 6글자 이름을 의미한다. 무제한인 `file*`보다 범위가 훨씬 좁다.
* **`{ }` (중괄호) vs `[ ]` (대괄호 / 스퀘어 브래킷)**:
  * **`file{1..50}`**: `file1`부터 `file50`까지의 연속된 파일 전체를 의미한다.
  * **`file[1-50]`**: 대괄호는 그 자리에 들어갈 수 있는 **한 글자의 후보군을 OR 조건 또는 범위로 지정**하는 것이다. 따라서 `[1-50]`은 1부터 50이 아니라, 5번째 자리에 **`1`부터 `5`까지의 숫자 또는 `0`**이 들어갈 수 있다는 뜻이므로 `file1`, `file2`, `file3`, `file4`, `file5`, `file0` 총 6개만 의미한다.
  * 복합 예시:
    * `file[1-37-9]`: 5번째 자리에 `1~3`(`1, 2, 3`) 또는 `7~9`(`7, 8, 9`)가 올 수 있음.
    * `file[1-379]`: 5번째 자리에 `1~3`(`1, 2, 3`) 또는 `7`, `9`가 올 수 있음(`8` 제외).
    * `file[1-379][6-8]`: 5번째 자리에 `1, 2, 3, 7, 9` 중 하나, 6번째 자리에 `6, 7, 8` 중 하나가 들어가는 모든 조합을 의미한다.

##### ④ 명령어 치환 기호: `` ` ` `` vs `$( )`
* **역따옴표(`` ` ` ``, 백틱)**와 **달러 소괄호(`$( )`)**는 둘 다 쉘이 해석할 때 **내부에 있는 문자열을 일반 글자가 아닌 '명령어'로 처리하여 실행**한다.
* 예: `echo date`는 글자 `date`를 출력하지만, ``echo `date` `` 또는 `echo $(date)`는 `date` 명령어를 먼저 실행한 뒤 그 결과값(현재 날짜와 시간)을 `echo`에게 넘겨 출력하게 한다.
* 역따옴표는 키보드 물결(`~`) 표시 자리에 쉬프트(Shift)를 누르지 않고 입력하는 기호인데, 글씨가 작으면 일반 작은따옴표(`'`)와 구분하기 힘들어 실무에서는 가독성이 좋은 **`$( )` 방식을 훨씬 더 선호한다**.

##### ⑤ 메타캐릭터 무력화(Quoting & Escaping) 기호: `\`, `' '`, `" "`
쉘이 메타캐릭터를 특수 기능으로 해석하지 못하도록 막고 순수 문자로 취급하게 만드는 세 가지 기호이다.

| 기호 | 명칭 | 무력화 범위 및 동작 특징 | 예외 사항 |
| :--- | :--- | :--- | :--- |
| **`\`** | 역슬래시 | 역슬래시 **바로 다음에 나오는 메타캐릭터 단 1개**만 쉘이 해석할 수 없도록 일반 문자로 만든다. (슈퍼맨의 힘을 빼앗는 크립토나이트와 같은 역할.) | 없음 (직후 문자 1개 무조건 무력화) (폰트에 따라 `₩`로 표시되기도 함) |
| **`' '`** | 작은따옴표 | 작은따옴표 **안에 둘러싸인 모든 메타캐릭터**를 쉘이 해석할 수 없도록 100% 일반 문자로 처리한다. | **예외 없음** (`$`, `` ` ``, `\` 등 모두 문자로 박제됨) |
| **`" "`** | 큰따옴표 (쌍따옴표) | 작은따옴표와 동일하게 내부 메타캐릭터를 문자로 처리하지만, **특정 3가지 기호는 쉘이 원래 기능대로 해석하도록 허용**한다. | **`$`(변수), `` ` ``(역따옴표), `\`(역슬래시)** 3가지는 메타캐릭터로 정상 동작함 (외우는 팁: "달러와 '역' 들어간 것 2개") |

## 3. 실습 과정 전체 통합 정리

수업 전체에서 진행된 실습은 **Client1 가상머신(CentOS/RHEL 계열, `root` 계정)** 환경과 호스트 **Windows** 환경을 오가며 진행되었다.

### 실습 1: `head` 명령어 옵션 복습 실습
* **실습 목적**: 파일 상단 일부 라인을 출력하는 `head` 명령어의 `-n` 옵션 동작을 확인한다.
* **입력 명령어**:
  ```bash
  head -n 5 /etc/passwd
  ```
* **실행 결과 및 확인 내용**:
  ```text
  [root@Client1 /root]# head -n 5 /etc/passwd
  root:x:0:0:root:/root:/bin/bash
  bin:x:1:1:bin:/bin:/sbin/nologin
  daemon:x:2:2:daemon:/sbin:/sbin/nologin
  adm:x:3:4:adm:/var/adm:/sbin/nologin
  lp:x:4:7:lp:/var/spool/lpd:/sbin/nologin
  ```
  [Part 1, 04:05, head -n 5 /etc/passwd 명령어로 상위 5개 라인을 출력한 화면]
  * `-n` 옵션으로 라인 개수를 지정할 수 있으며, `-n` 글자 없이 숫자만(`-5`) 입력해도 동일하게 동작한다.

### 실습 2: `file` 명령어를 활용한 파일 유형 식별 및 `cat` 열람 검증
* **실습 목적**: 시스템 내 여러 파일들의 실제 유형을 `file` 명령어로 판별하고, 어떤 유형의 파일을 `cat`으로 열람할 수 있는지 검증한다.
* **실행 순서 및 결과**:
  1. **일반 텍스트 파일 확인 및 출력**:

     * `grep ^telnet /etc/services`: `-w`를 빼면 단어가 아닌 글자 기준이므로 `telnet`뿐만 아니라 `telnets`, `telnetcpcd`로 시작하는 라인까지 함께 출력된다.

     ```bash
     vi abc.txt
     grep ^test abc.txt
     grep ^test$ abc.txt
     rm -rf abc.txt
     ```
     * `grep ^test abc.txt`를 실행하면 라인이 `test`로 시작하므로 해당 줄이 출력되지만, `grep ^test$ abc.txt`를 실행하면 아무것도 출력되지 않는다. 이를 통해 `^test$`는 양끝에 `test`가 있는 줄이 아니라, **한 라인에 오로지 `test`라는 단어 딱 하나만 있는 줄**을 의미함을 확인한 뒤 `rm -rf abc.txt`로 임시 파일을 삭제하였다.
     [Part 1, 24:14, abc.txt를 대상으로 grep ^test와 grep ^test$의 결과를 비교 검증한 화면]

### 실습 5: `wc` 통계 확인 및 `su -` 계정 전환 실습
* **실습 목적**: 파일의 라인/단어/글자 수를 세는 `wc`를 파이프라인과 결합하여 시스템 통계를 산출하고, `su -`를 통해 계정을 전환한다.
* **실행 순서 및 결과**:
  1. **`wc` 단일 파일 측정 및 `ls -l` 크기 대조**:

     ```bash
     wc -l /etc/passwd
     wc -w /etc/passwd
     wc -c /etc/passwd
     ```
     * `wc /etc/passwd` 실행 시 `39  89 2174 /etc/passwd`가 출력된다 (39라인, 89단어, 2174글자).
     * `ls -l /etc/passwd`에 표시되는 파일 크기(바이트 수)인 `2174`가 `wc`의 글자 수(`2174`)와 정확히 일치함을 확인하였다. `-l`, `-w`, `-c` 옵션으로 각각 따로 출력할 수도 있다.
     [Part 2, 20:40, wc /etc/passwd의 글자 수(2174)와 ls -l의 파일 크기를 비교 확인한 화면]
  2. **파이프라인(`|`)과 `wc -l`을 결합한 시스템 통계 산출**:
     ```bash
     rpm -qa
     rpm -qa | wc -l
     ps -ef
     ps -ef | wc -l
     ps -ef | head
     ls -l /etc | wc -l
     ls -l /etc | head
     ```
     * Windows 제어판의 '프로그램 및 기능'에서는 하단에 설치된 프로그램 개수(예: 105개)를 보여주지만, Linux의 `rpm -qa`는 목록만 출력할 뿐 총 개수를 알려주지 않는다. 이때 `rpm -qa | wc -l`을 실행하면 라인 수를 세어 현재 **1,187개**의 패키지가 설치되어 있음을 즉시 알 수 있다.

     ```bash
     date
     ```

       * `dat || cal`: 앞이 실패했으므로 뒤의 달력을 **대신 실행하여 출력**한다.

## 4. 명령어 및 터미널 내용 통합 정리

수업 전체에서 직접 실행하거나 교재/화면을 통해 분석한 주요 명령어들의 상세 명세이다.

### 4.1 파일 유형 및 내용 확인 명령어

#### `file`
* **원문 및 사용 사례**:
  ```bash
  file /etc/passwd
  file /etc
  file /usr/bin/ls
  file /usr/bin/mkdir
  file /var/run/utmp
  file /usr/bin/lesspipe.sh
  file /etc/NetworkManager/system-connections/ens33.nmconnection
  file /usr/bin/gettext.sh
  file /usr/sbin/ifconfig
  ```
* **기능 및 목적**: 지정한 대상 파일이 어떤 데이터 형식(ASCII 텍스트, 디렉터리, ELF 바이너리 실행 파일, 데이터, 쉘 스크립트 등)인지 판별하여 알려준다.
* **주의사항**: 파일을 `cat` 등으로 열람하기 전에 텍스트 파일인지 바이너리 파일인지 구분하기 위해 사용한다.

#### `cat` / `head` / `tail` / `more`
* **원문 및 사용 사례**:
  ```bash
  head -n 5 /etc/passwd
  cat /etc/passwd
  cat /usr/bin/ls
  cat /usr/bin/lesspipe.sh
  ```
* **기능 및 옵션**:
  * `cat`: 텍스트 파일의 전체 내용을 출력한다 (`-n`: 줄 번호 표시).
  * `head`: 파일의 위에서부터 지정한 줄 수(`-n`) 또는 글자 수(`-c`)만큼 출력한다.
  * `tail`: 파일의 아래에서부터 지정한 줄 수(`-n`) 또는 글자 수(`-c`)만큼 출력한다 (`-f`: 실시간 로그 확인 시 사용).
  * `more`: 화면 단위로 끊어서 출력한다.

### 4.2 텍스트 및 파일 검색 명령어

#### `grep` / `egrep`
* **원문 및 사용 사례**:
  ```bash
  grep telnet /etc/services
  grep -w telnet /etc/services
  grep -w ^telnet /etc/services
  grep ^telnet /etc/services
  grep Controller /etc/services
  grep Controller$ /etc/services
  grep ^test abc.txt
  grep ^test$ abc.txt
  cat /etc/services | grep telnet
  ls -l /etc | grep issue
  env | grep PATH
  cat /etc/passwd | egrep "^root|^user"
  ```
* **기능 및 목적**: 파일이나 파이프로 전달된 출력 내용 안에서 특정 숫자, 문자, 단어, 문자열 패턴을 검색하여 일치하는 라인을 출력한다.
* **주요 옵션 (교재 및 실습 포함)**:
  * `-w`: 단어(Word) 기반 검색.
  * `-v`: 지정한 패턴을 제외하고(반전하여) 검색.
  * `-i`: 대소문자를 구분하지 않고 검색 (기본적으로 Linux는 대소문자를 엄격히 구분함).
  * `-E` (또는 `egrep`): 확장 정규 표현식을 사용하여 여러 개를 동시에 검색(예: `"^root|^user"`)할 때 사용.

#### `whereis` / `which`
* **원문 및 사용 사례**:
  ```bash
  whereis ls
  which ls
  whereis mkdir
  whereis ifconfig
  whereis cp
  which cp
  whereis passwd
  which passwd
  ```
* **기능 및 차이점**:
  * `whereis`: `$PATH` 환경 변수와 관계없이 파일(실행 파일, 설정 파일, 매뉴얼 파일)의 위치를 광범위하게 검색한다.
  * `which`: `$PATH` 환경 변수에 등록된 디렉터리 내부에서만 실행 파일을 검색하며, `alias` 설정 여부도 함께 출력한다.

#### `find`
* **원문 및 사용 사례**:
  ```bash
  find / -name httpd
  find / -name httpd -type f
  find / -name httpd -type d
  find --help
  find /etc -name pass*
  find /etc -name *conf
  ```
* **기능 및 옵션**:
  * 첫 번째 인자로 검색을 시작할 디렉터리 경로(`/`, `/etc` 등)를 지정한다.
  * `-name <패턴>`: 지정한 이름(와일드카드 `*` 사용 가능)과 일치하는 대상을 찾는다.
  * `-type f`: 일반 파일(File)만 검색한다.
  * `-type d`: 디렉터리(Directory)만 검색한다.

### 4.3 환경 변수, 시스템 관리 및 쉘 제어 명령어

#### `env` / `echo`
* **원문 및 사용 사례**:
  ```bash
  env
  echo PATH
  echo $PATH
  echo $SHELL $HOSTNAME
  echo $ABC
  echo date
  echo `date`
  echo $(date)
  echo \$HOSTNAME
  echo \$PATH
  echo '$PATH'
  echo '$PATH $SHELL'
  echo "$PATH"
  ```
* **기능 및 목적**: `env`는 시스템 환경 변수 전체 목록을 출력하고, `echo`는 입력받은 문자열이나 변수값(`$변수명`), 명령어 치환 결과(`` `명령` ``, `$(명령)`)를 화면에 출력한다.

#### `wc` (Word Count)
* **원문 및 사용 사례**:
  ```bash
  wc /etc/passwd
  wc -l /etc/passwd
  wc -w /etc/passwd
  wc -c /etc/passwd
  rpm -qa | wc -l
  ps -ef | wc -l
  ls -l /etc | wc -l
  ```
* **기능 및 옵션**: 대상 파일이나 표준 출력의 라인 수(`-l`), 단어 수(`-w`), 글자/바이트 수(`-c`)를 카운트한다.

#### `su` (Switch User) / `id` / `whoami` / `exit`
* **원문 및 사용 사례**:
  ```bash
  su - user1
  id
  whoami
  su - user2
  exit
  ```
* **기능 및 목적**: `su - <계정명>`으로 해당 계정의 환경 변수를 로드하며 사용자를 전환하고, `id`(UID, GID, 그룹 정보 출력)와 `whoami`(현재 계정명 출력)로 신원을 확인한 뒤 `exit`로 로그아웃한다.

#### 기타 시스템 확인 명령어 (`alias`, `ifconfig`, `time`, `rpm`, `ps`, `chsh`, `date`, `cal`, `uname`)
* **`alias`**: 현재 설정된 명령어 별칭 목록을 확인한다.
* **`ifconfig`**: 네트워크 인터페이스(`ens33`, `lo`)에 설정된 IP 주소 등을 확인한다.
* **`time <명령어>`**: 해당 명령어를 검색하고 실행하는 데 걸리는 시간(`real`, `user`, `sys`)을 측정한다.
* **`rpm -qa`**: 현재 Linux 시스템에 설치된 모든 RPM 패키지 목록을 출력한다.
* **`ps -ef`**: 현재 실행 중인 모든 프로세스의 상세 정보(`UID`, `PID`, `PPID`, `CMD` 등)를 출력한다.
* **`chsh -l`**: 시스템에서 사용 가능한 쉘(Shell) 목록을 확인한다.
* **`date` / `cal` / `uname -a`**: 각각 현재 날짜/시간, 달력, 시스템 커널 및 아키텍처 정보를 출력한다.

| **`/etc`** | directory | 시스템 환경 구성 파일(`.conf`, `.cfg`, `.cf`)들이 모여 있는 디렉터리 | `file /etc`로 디렉터리 유형 확인, `ls -l /etc \| grep issue`, `ls -l /etc \| wc -l`(236개 항목 확인), `find /etc -name pass*`, `find /etc -name *conf` 실습 |
| **`/usr/bin/ls`**, **`/usr/bin/mkdir`** | ELF 실행 파일 | 기본 명령어들의 실제 바이너리 프로그램 파일 | `file`로 ELF 바이너리 확인, `cat /usr/bin/ls` 출력 시 깨짐 확인, `whereis` 및 `which`로 경로 확인, `$PATH` 연동 실행 확인 |
| **`/usr/sbin/ifconfig`** | ELF 실행 파일 | 네트워크 인터페이스 확인 및 설정 실행 파일 | `file`로 ELF 확인(예제 4번), `whereis ifconfig`로 위치 확인, `time ifconfig`로 실행 시간 측정 |
| **`/var/run/utmp`** | data | 시스템 로그인 상태 관련 데이터 파일 | `file /var/run/utmp`를 통해 글자와 데이터가 혼합된 `data` 유형 확인 |
| **`/usr/bin/lesspipe.sh`**, **`/usr/bin/gettext.sh`** | 쉘 스크립트 (`ASCII text executable`) | 텍스트 코드로 작성된 쉘 스크립트 실행 파일 | `file`로 유형 확인 및 `cat`으로 내부 스크립트 코드가 정상 출력됨을 확인(예제 3번) |
| **`/etc/NetworkManager/system-connections/ens33.nmconnection`** | ASCII text | 네트워크 어댑터(`ens33`) 연결 설정 파일 | `file` 명령어로 `ASCII text`임을 확인하여 `cat` 열람 가능 판별(예제 1번) |
| **`/root/abc.txt`** | 임시 파일 | `^test$` 정규 표현식 검증을 위해 생성한 테스트 파일 | `vi abc.txt`로 생성 후 `grep ^test$ abc.txt` 테스트 완료 뒤 `rm -rf abc.txt`로 삭제 완료 |
| **`/root/test/file3`** | 임시 파일 | 교재 `sort` 및 `cat << EOF` 예제용 파일 | Part 3 시작 시점에 `rm -rf file3` 및 `ls` 명령으로 삭제 완료된 상태로 확인됨 |
| **`PATH` (환경 변수)** | 환경 변수 | 실행 파일 자동 검색 디렉터리 목록 | 기본값: `/root/.local/bin:/root/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin` (`echo $PATH`로 확인) |

## 6. 오류 및 문제 해결 과정 통합 정리

### 사례 1: ELF 바이너리 실행 파일을 `cat`으로 열람 시 화면 깨짐 현상
* **발생 문제**: `cat /usr/bin/ls` 실행 시 터미널 화면에 읽을 수 없는 기호와 이상한 문자열(`256colorxterm` 반복 등)이 대량 출력됨.
* **원인**: `/usr/bin/ls`는 글자(ASCII text)가 아니라 컴파일러에 의해 기계어(0과 1의 바이너리)로 변환된 ELF 실행 프로그램이기 때문에 사람이 읽을 수 있는 형태로 출력되지 않는다.
* **해결 및 예방**: 정체를 모르는 파일은 무작정 `cat`으로 열지 말고 반드시 `file <파일경로>` 명령어로 파일 유형을 먼저 확인하여, `ASCII text`가 포함된 파일만 텍스트 뷰어로 열람해야 한다.

### 사례 2: `echo PATH` 입력 시 환경 변수 경로가 나오지 않는 문제
* **발생 문제**: `PATH` 환경 변수에 등록된 디렉터리 목록을 보려고 `echo PATH`를 입력했으나 단순히 `PATH`라는 글자만 출력됨.
* **원인**: 변수 이름 앞에 `$` 기호를 붙이지 않으면 쉘은 이를 변수가 아닌 일반 문자열로 인식한다.
* **해결**: `echo $PATH`와 같이 변수명 앞에 달러(`$`)를 붙여 실행하면 변수 내부의 디렉터리 경로 값이 정상 출력된다.

### 사례 3: 일반 계정 간 `su -` 전환 시 인증 실패 오류
* **발생 문제**: `user1` 계정 상태에서 `su - user2`를 실행하고 암호를 입력했으나 `su: 인증 실패` 메시지가 출력되며 전환이 거부됨.
* **원인**: `root`에서 일반 계정으로 갈 때와 달리 일반 계정 간 전환 시에는 대상 계정의 암호를 정확히 입력해야 하는데, 암호(`centos`) 입력 중 오타가 발생함.
* **해결**: 다시 `su - user2`를 실행하고 정확한 암호를 입력하여 `user2`로 정상 로그인하였다.

### 사례 4: `wc -l`을 이용한 개수 산출 시 실제 개수보다 1개 더 많게 나오는 문제
* **발생 문제**: `ps -ef | wc -l`과 `ls -l /etc | wc -l` 실행 시 둘 다 `237`이 나왔으나 실제 프로세스 및 파일 개수는 236개임.
* **원인**: `ps -ef`의 맨 첫 줄에는 필드 제목(`UID PID PPID...`)이 출력되고, `ls -l`의 맨 첫 줄에는 블록 크기 합계(`합계 1308`)가 출력되는데, `wc -l`은 이 첫 번째 헤더 줄까지 포함하여 라인 수를 세기 때문이다.
* **해결**: 명령어 출력에 헤더 라인이 포함되는지 `| head` 등으로 확인한 뒤, 전체 라인 수에서 헤더 라인 수(1줄)를 빼고 계산해야 한다.

### 사례 5: 고의 오타(`dat`)를 통한 명령어 연결 연산자(`;`, `&&`, `||`) 동작 검증
* **발생 상황**: `date` 명령어를 일부러 `dat`로 잘못 입력하여 `bash: dat: 명령을 찾을 수 없습니다...` 오류를 발생시킴.
* **연산자별 결과**:
  * `dat ; cal`: 앞의 오류와 무관하게 뒤의 `cal`이 실행됨.
  * `dat && cal`: 앞이 오류를 냈으므로 뒤의 `cal`이 실행되지 않고 중단됨.
  * `dat || cal`: 앞이 오류를 냈기 때문에 뒤의 `cal`이 실행됨.

## 7. 강사의 강조사항 및 학습 포인트

### 1) 자격증 시험 및 실무 빈출 비교 포인트
* **`whereis` vs `which`**:
  * 자격증 시험은 문제 은행(뺑뺑이) 방식이므로 두 명령어의 차이를 묻는 문제가 자주 출제된다.
  * **`which`**는 오직 **`$PATH` 환경 변수에 등록된 디렉터리**에서만 찾고 `alias` 정보를 함께 보여주며, **`whereis`**는 `$PATH`와 관계없이 설정 파일과 매뉴얼 파일까지 포함하여 더 넓은 범위를 찾는다.
* **`su` vs `su -`**:
  * 하이픈(`-`)이 없는 `su user1`은 이전 계정(`root`)의 환경 변수를 그대로 쓰고, 하이픈이 있는 **`su - user1`은 로그인한 대상 계정(`user1`)의 환경 변수를 새로 불러와 사용**한다.
* **작은따옴표(`' '`) vs 큰따옴표(`" "`) vs 역슬래시(`\`) 보너스 문제 주의**:
  * 시험에서 따옴표와 `$변수` 출력 결과를 묻는 문제는 절대 틀리면 안 되는 보너스 문제이다.
  * 작은따옴표(`' '`)는 예외 없이 내부의 모든 메타캐릭터를 문자로 만들지만, **큰따옴표(`" "`)는 달러(`$`), 역따옴표(`` ` ``), 역슬래시(`\`) 3가지를 예외로 두어 쉘이 그대로 해석**하게 한다.
  * 문제 지문을 읽을 때 따옴표나 역슬래시가 앞의 변수에만 붙어 있는지(`echo '$HOSTNAME' $SHELL`), 전체에 붙어 있는지(`echo '$HOSTNAME $SHELL'`) 범위를 정확히 확인해야 함정에 빠지지 않는다.

### 2) 초보자가 자주 혼동하는 정규 표현식 및 옵션 주의사항
* **`grep`에서 `-w` 유무의 차이**: `-w`를 넣어야 단어(Word) 검색이 되며, 빼면 단순 글자 포함 검색이 된다.
* **`^test$`의 정확한 의미**: 시작이 `test`이고 끝이 `test`라고 해서 `test ... test` 문장이 검색되는 것이 아니라, 한 줄 전체에 오로지 `test`만 단독으로 적혀 있어야 한다.
* **`file{1..50}`과 `file[1-50]`의 차이**: 중괄호 `{1..50}`은 1부터 50까지이지만, 대괄호 `[1-50]`은 한 자리 문자에 대한 OR 조건이므로 `1~5` 또는 `0`(`file1`~`file5`, `file0`)만을 의미한다.
* **피리어드(`.`)와 별(`*`)의 차이**: `file.`은 딱 5글자(뒤에 1자리 모든 문자)만 의미하지만, `file*`은 `file`(4글자)을 포함해 길이 제한 없이 `file`로 시작하는 모든 것을 의미한다.
* **`rm -rf *` 절대 사용 금지**: 애스터리스크(`*`)는 전체를 의미하므로, 작업 디렉터리를 잘못 둔 상태에서 `rm -rf *`를 실행하면 모든 파일이 강제 삭제되므로 실무에서 극히 주의해야 한다.

## 8. 정보보안 관련 추가 정리

수업 중 강사가 직접 언급하고 시연한 정보보안 및 해킹 공격/방어 관련 핵심 내용이다.

### 1) OS Command Injection (운영체제 명령어 삽입 공격)의 원리
* **수업에서 다룬 내용**:
  * 강사는 세미콜론(`;`), 더블 앰퍼샌드(`&&`), 더블 버티컬 바(`||`)를 설명하면서, 공격자들이 시스템 해킹 시 이러한 메타캐릭터를 악용하는 공격 기법을 **OS Command Injection(명령어 인젝션) 공격**이라고 소개하였다.
  * 특히 세미콜론(`;`)은 앞의 명령어가 오류가 나든 말든 뒤에 입력한 명령어를 무조건 실행시켜 주므로 공격자들이 가장 즐겨 사용한다.
  * 강사는 "살인 도구나 방법의 본질이 옛날과 똑같듯이, 해킹 공격 기법도 다 옛날부터 있던 공격인데 과정만 조금씩 바뀔 뿐 지금도 여전히 똑같이 시도되고 있고 당하고 있다"고 강조하였다.
* **보안적 이해를 위한 보충 설명**:
  * 웹 애플리케이션 등이 사용자의 입력값을 적절한 검증 없이 시스템 쉘 명령어 인자로 전달할 때, 공격자가 `; rm -rf /`나 `; cat /etc/passwd` 같은 구문을 뒤에 붙여 원하는 시스템 명령어를 무단 실행시키는 치명적인 취약점이다.

### 2) 역슬래시(`\`) 이스케이프를 활용한 공격 방어 원리
* **수업에서 다룬 내용**:
  * 공격자가 `;`나 `&&` 같은 메타캐릭터를 입력하여 공격할 때, 이를 방어하는 가장 기본적인 방법은 해당 메타캐릭터 앞에 **역슬래시(`\`)**가 들어가도록 처리(예: `\;`)하는 것이다.
  * 슈퍼맨이 크립토나이트 돌덩이 앞에서는 힘을 잃고 일반인보다 못하게 되듯, 아무리 강력한 메타캐릭터라도 앞에 역슬래시(`\`)가 붙으면 특수 능력을 상실하고 평범한 일반 글자(문자)로 전락하기 때문에 명령어가 실행되지 않아 공격이 무력화된다.

## 9. 최종 복습 자료

### 9.1 주요 개념 요약
* **파일 유형**: Linux는 모든 것(디렉터리, 명령어 포함)을 파일로 다루며, `cat`으로는 `ASCII text` 및 `script`(쉘 스크립트)만 볼 수 있고 `ELF`(기계어 실행 파일)나 `data`는 볼 수 없다.
* **`PATH` 환경 변수**: 명령어 실행 파일이 위치한 디렉터리들을 등록해 두어, 경로 입력 없이 명령어 이름만으로 어디서든 실행할 수 있게 해주는 환경 변수이다.
* **쉘(Shell)**: 사용자의 명령어를 해석해 커널에 전달하는 중계자(기본 `bash`)이며, 실행되는 명령어들의 부모 프로세스(`PPID`)가 된다.
* **메타캐릭터 제어**: `;`(무조건 순차 실행), `&&`(성공 시 실행), `||`(실패 시 실행)로 프로세스 흐름을 제어하며, `\`, `' '`, `" "`로 메타캐릭터의 해석 여부를 통제한다.

### 9.2 주요 명령어 치트시트

| 명령어 | 주요 옵션 | 기능 | 수업에서의 사용 목적 |

| **`whereis`** | 없음 | 파일/매뉴얼 전체 경로 검색 | `$PATH` 무관하게 실행 파일, 설정 파일, 매뉴얼 위치 일괄 확인 |

| **`find`** | `-name`, `-type f/d` | 디렉터리 트리 정밀 검색 | `/` 및 `/etc` 하위에서 `httpd`, `pass*`, `*conf` 파일/폴더 검색 |
| **`wc`** | `-l`, `-w`, `-c` | 줄, 단어, 글자 수 카운트 | `/etc/passwd` 크기 확인 및 `rpm -qa \| wc -l` 패키지 수 집계 |
| **`su`** | `-` (환경 변수 로드) | 사용자 계정 전환 | `root` $\rightarrow$ `user1` $\rightarrow$ `user2` 계정 전환 및 권한/암호 확인 |
| **`chsh`** | `-l` | 사용 가능 쉘 목록 출력 | 시스템에 설치된 쉘(`/bin/bash` 등) 목록 확인 |
| **`ps`** | `-ef` | 실행 중인 프로세스 확인 | 프로세스 총 개수 카운트 및 `bash` 쉘의 `PPID` 추적 |

### 9.3 실습 복습 가이드
1. **파일 유형 판별**: `file /etc/passwd`, `file /usr/bin/ls`, `file /usr/bin/lesspipe.sh`를 차례로 실행하여 출력 메시지를 비교하고, 텍스트와 스크립트만 `cat`으로 열어본다.
2. **정규 표현식 검색**: `grep telnet /etc/services`, `grep -w telnet /etc/services`, `grep -w ^telnet /etc/services`, `grep Controller$ /etc/services`를 순서대로 실행하며 검색 결과가 좁혀지는 과정을 확인한다.
3. **환경 변수 및 경로 검색**: `echo $PATH`로 등록된 경로를 확인한 뒤, `whereis passwd`와 `which passwd`를 실행하여 출력 범위를 비교하고, `find /etc -name *conf -type f`로 설정 파일을 검색한다.
4. **파이프라인 통계 및 계정 전환**: `rpm -qa | wc -l`과 `ps -ef | wc -l`을 실행해 개수를 확인하고, `su - user1` $\rightarrow$ `su - user2` $\rightarrow$ `exit` $\rightarrow$ `exit` 순서로 계정 전환과 복귀를 연습한다.
5. **메타캐릭터 및 쿼팅 검증**: `dat ; cal`, `dat && cal`, `dat || cal`로 오류 시 동작을 비교하고, `echo \$PATH`, `echo '$PATH'`, `echo "$PATH"`를 각각 실행하여 변수 치환 여부를 확인한다.

### 9.4 주의사항 및 자주 혼동하는 내용
* `$` 기호는 뒤에 오면(`bash$`) **라인의 끝**이고, 앞에 오면(`$PATH`) **변수 이름**이다.
* `find` 명령어의 `-name`, `-type` 옵션은 단어 형태이지만 대시를 2개(`--`)가 아닌 **1개(`-`)만** 사용한다.
* 큰따옴표(`" "`)는 메타캐릭터를 문자로 만들지만 **`$`, `` ` ``, `\` 세 가지는 예외적으로 쉘이 해석**하므로 `"$PATH"`는 변수값이 출력된다.
* 대괄호 `[1-50]`은 1부터 50이 아니라 **`1, 2, 3, 4, 5, 0` 중 한 자리 글자**를 의미한다.
