리눅스 실습 환경 구축 및 파일 시스템, 기본 명령어 학습 기록

리눅스 서버 실습을 위한 가상 환경(VM) 구축과 파일 시스템(FHS) 및 기본 디렉터리 이동 명령어에 대해 학습한 내용을 정리한다. 향후 웹이나 DB 서버 구축을 위한 뼈대가 되는 필수적인 환경 설정과 시스템 내부를 이동하는 기동력을 익히는 과정이었다.

전체적인 학습 내용은 가상 환경 및 네트워크를 점검하는 Part 1과, 파일 시스템의 뼈대를 파악하고 터미널에서 이동하는 실습을 진행한 Part 2, 3으로 나누어 기록했다.

Part 1 - 실습 환경 구축 및 네트워크 통신 검증
가장 먼저 1대의 호스트 PC(Windows) 위에 4대의 CentOS 가상 머신(Client1, Client2, Server1, Server2)을 구동하여 상호 작용할 수 있는 환경을 구축했다. 본체 성능 저하를 막기 위해 호스트 PC의 메모리는 16GB, 디스크 여유 공간은 50GB 이상이 필요한 환경이다.

1. 가상 머신(VM) 실행 및 로그인
Windows 탐색기 상단 메뉴의 '보기' 탭에서 '파일 확장명'에 체크하여 확장자가 보이도록 설정한 후, 4개의 폴더에 있는 .vmx 파일을 더블클릭하여 VMware에 등록하고 부팅했다.

로그인 계정: 사용자 이름 root, 암호 centos

정보보안 관점의 참고: 실습 편의를 위해 최고 관리자인 root 계정으로 로그인했으며, 비밀번호 역시 내부 실습용 가상환경이므로 유추하기 쉬운 취약한 문자열(centos)을 사용했다.

2. 네트워크 장치 및 IP 확인
각 가상 머신에 정상적으로 IP가 할당되었는지 확인하기 위해 터미널을 열고 다음 명령어를 실행했다.

Bash
ip address
실행 결과: ens33 인터페이스에 할당된 IP를 확인했다. 192.168.2.201/24 (Client1 기준)과 같이 192.168.2.201~204 대역의 IP가 표시되었다. 호스트 내부 네트워크망과 통신할 수 있는 논리적 주소가 정상적으로 확보되었음을 의미한다.

3. 라우팅(게이트웨이) 확인
인터넷으로 나가는 관문이 제대로 설정되어 있는지 확인했다. clear (또는 Ctrl+L)로 화면을 지운 후 실행했다.

Bash
ip route
실행 결과: default via 192.168.2.254 dev ens33 proto static metric 100 내용이 출력되며, 기본 게이트웨이 IP가 192.168.2.254로 설정되어 있음을 확인했다.

4. DNS 설정 확인
도메인 네임 서버 설정 파일의 내용을 확인했다. 강사님께서 이 기능은 '114 전화번호부'와 같다고 설명하셨다.

Bash
cat /etc/resolv.conf
실행 결과: nameserver 168.126.63.1 이라는 출력을 확인했다. KT에서 제공하는 DNS 서버가 설정되어 도메인 이름을 IP로 변환할 수 있는 상태다.

5. 외부 통신(DNS 및 Ping) 테스트
네트워크 외부 통신과 도메인 변환이 실제 정상 작동하는지 검증했다. 패킷을 무한히 보내지 않기 위해 -c 3 옵션을 사용했다.

Bash
ping -c 3 168.126.63.1
실행 결과: 3 packets transmitted, 3 received, 0% packet loss가 출력되며 통신이 원활함을 확인했다.

Bash
nslookup www.naver.com
실행 결과: Server IP(168.126.63.1)를 통해 Naver의 실제 IP 주소들(223.130.192.247 등)을 성공적으로 받아왔다. 이 명령어들은 복사 후 다른 VM 창에서 Shift + Insert로 붙여넣기 하여 빠르게 실습할 수 있었다.

발생한 오류 및 트러블슈팅
오류 현상: 실습 중 특정 Windows 11 환경에서 보안 정책 등으로 인해 ens33 네트워크 장치가 비활성화(Down)되거나 IP가 나타나지 않는 문제가 발생했다.

해결 및 주의사항: 강사님께서 직접 개별적으로 조치를 취해주셨다. 강사님은 Ping이 안 나가거나 IP가 다를 경우 통신망에 문제가 생긴 것이므로, 절대 혼자 고민하지 말고 즉시 말해달라고 매우 강력하게 강조하셨다.

Part 2 & 3 - 리눅스 파일 시스템(FHS) 이해와 CLI 내비게이션
네트워크 설정이 완료된 후, 리눅스의 내부 뼈대인 파일 시스템 구조를 파악(Part 2)하고, 터미널 환경에서 명령어와 특수 기호를 통해 자유자재로 이동(Part 3)하는 실습을 진행했다.

1. AWS 클라우드 환경 접속 시연 관전 (Part 2)
명령어 실습 전, 실무 환경을 엿보기 위해 강사님의 AWS EC2 인스턴스 생성 시연을 보았다. 인스턴스 ID i-0d05af69b9916473d (MyWeb), Public IP 13.209.74.5, Private IP 172.31.44.93, OS 이미지 Amazon Linux 2023 환경을 1분 만에 생성하는 것을 보며, 실무에서는 OS 직접 설치보다 클라우드에서 생성하여 원격 터미널로 접속해 관리한다는 점을 학습했다.

2. 리눅스 디렉터리 계층 구조(FHS) 학습 (GUI 활용)
CentOS 바탕화면에서 파일 탐색기를 열어 다른 위치 > 컴퓨터를 클릭해 시스템 주요 폴더들을 눈으로 확인했다.

/ (루트 디렉터리): 리눅스 파일 시스템의 최상위 디렉터리. Windows의 C드라이브와 같다. (초보자가 /root와 이름을 헷갈리기 쉬우나 완전히 구분해야 한다고 강사님께서 강조하셨다.)

/root: root 계정(최고 관리자)의 홈 디렉터리. 로그인 시 기본 위치다.

/home: 일반 사용자(fedora, user1, user2 등)들의 홈 디렉터리. 관리자와 권한이 분리된다.

/bin: 일반적인 명령어 실행 파일 보관소 (ls, cat 등).

/sbin: 포맷, 파티션 분할 등 시스템 관리용 명령어 보관소.

/etc: 네트워크, 서비스 등 시스템 전반의 환경 설정 파일 보관소.

/usr: 일반 프로그램(서비스) 실행 파일 보관소.

/var: 가변 데이터 및 로그(Log) 파일 보관소.

/dev: 하드디스크, 키보드 등 물리적 장치 파일 보관소.

강사님 강조 사항 및 보안 관점: 윈도우는 특정 프로그램 설치 시 하나의 폴더에 모든 것이 모이지만, 리눅스는 용도에 따라 /usr(실행), /etc(설정), /var(로그)로 분산 저장됨을 반드시 인지해야 한다고 하셨다. 특히 /var는 시스템 오류 분석이나 보안 공격 침해 시 가장 먼저 확인해야 하는 일기장 역할을 한다. 또한 관리자(/root)와 일반 사용자(/home)의 공간 분리는 권한과 접근제어의 가장 기본 구조가 된다.

3. CLI 환경을 이용한 경로 탐색 실습 (Part 3)
GUI로 파악한 구조를 바탕으로 터미널을 열어 직접 이동해보는 실습을 진행했다.

학습한 명령어 및 특수 기호

pwd: 현재 작업 디렉터리의 절대 경로 출력

ls: 현재 디렉터리 내의 파일 및 하위 폴더 목록 출력 (파란색은 디렉터리를 의미)

cd: 지정된 경로로 이동 (주의: 명령어 뒤에 반드시 띄어쓰기 한 칸을 해야 하며, 인자로 파일 이름은 올 수 없다)

경로 지정 방식:

절대 경로: 무조건 최상위 / 부터 시작하는 방식 (예: /etc/sysconfig/network-scripts/)

상대 경로: 현재 위치(.)를 기준으로 계산하는 방식 (예: cd ..)

특수 기호:

cd /: 루트 디렉터리로 이동

cd .: 현재 디렉터리

cd ..: 한 단계 상위(부모) 디렉터리로 이동

cd -: 이동하기 직전의 작업 디렉터리로 복귀

cd ~ (또는 인자 없는 cd): 현재 로그인한 사용자의 홈 디렉터리로 즉시 복귀

터미널 경로 이동 실습 흐름

pwd를 입력하여 현재 위치가 /root 임을 확인했다.

cd /를 입력해 최상위 디렉터리로 이동 후, ls를 쳐서 etc, usr, var, boot 등의 하위 디렉터리 목록을 확인했다.

단계별 이동을 위해 cd etc, 이후 cd sysconfig를 차례로 입력했다.

강사님이 가장 강조하신 Tab 키 자동완성을 실습했다. cd net까지 치고 Tab을 눌러 자동완성 목록을 확인한 뒤 /etc/sysconfig/network-scripts 디렉터리로 무사히 진입했다. 복잡한 경로를 칠 때는 Tab 키가 선택이 아닌 필수라고 하셨다.

cd ..을 입력하여 현재 위치에서 한 단계 위인 /etc/sysconfig로 상대 경로 이동을 해보았다.

이번에는 절대 경로인 cd /etc/sysconfig/network-scripts/를 전체 입력하여 한 번에 목적지로 이동하는 것을 확인했다.

마지막으로 cd -를 쳐서 직전 경로로 돌아가고, cd ~를 입력하여 홈 디렉터리인 /root로 한 번에 순간 이동하며 내비게이션 실습을 마쳤다.

오류 및 해결 기록 (Part 3)

오류 1: ls: cannot access '/b': 그런 파일이나 디렉터리가 없습니다

원인: /boot 디렉터리를 조회하려 했으나 오타로 인해 /b로 잘못 입력함 [확인 필요].

해결: ls /boot로 정확한 경로를 다시 입력하여 내부의 vmlinuz 파일 등 목록을 정상 출력했다.

오류 2: -bash: cd: /etc/sysconfig/network-scripts:: 그런 파일이나 디렉터리가 없습니다

원인: 경로 마지막에 콜론(:)이 잘못 입력되어 존재하지 않는 경로로 인식됨.

해결: 오타로 인해 bash 셸에서 에러를 반환한 것이며, 올바른 경로로 재입력해야 했다. 이 때문에 Tab 키 자동완성을 써야 오타를 막을 수 있다.
